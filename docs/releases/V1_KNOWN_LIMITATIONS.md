# Personal AI Workbench V1 — Known Limitations

**Version: 1.0.0.** **Status: RELEASE READY.** **Platform: Windows x64.** **Gate C: PASS.**

Shipping did not retire any entry below, and no entry was added for the release. Unverified areas stay
recorded as unverified: the real dual-harness handoff is `UNAVAILABLE` in the final acceptance
environment (only the Codex CLI is installed — see `V1_ACCEPTANCE.md`), browser download/upload was
not exercised, UI review is DOM/accessibility-level rather than pixel-level (D4), Office visual
fidelity was not verified by hand (O2), mid-flight hard-kill recovery was not verified by hand, and
Chromium's asynchronous profile flush timing is unverified for an immediate hard kill (B5).

Every entry was observed in the V1 source, not inferred from a specification. `Impact` states what a
user actually loses; `Workaround` says what to do instead, or `none` when there is no alternative.

## Harness and handoff

| #   | Limitation                                                                                                                                                             | Impact                                                                             | Workaround                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| H1  | The Model Gateway can only be pointed at `codex` and `claudeAgent`. Cursor, Grok, Antigravity, OpenCode and every Generic ACP harness report `unsupported-by-harness`. | Those harnesses cannot use Workbench routes, failover or gateway usage accounting. | Run the harness on its own provider settings (Native). Nothing else is affected. |
| H2  | A handoff is refused while a turn is running ("Thread '<id>' is busy").                                                                                                | You cannot queue a switch for the end of the current turn.                         | Stop the turn, then hand off.                                                    |

## Model Gateway

| #   | Limitation                                                                                                                                                                                | Impact                                                                                                  | Workaround                                                                                   |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| G1  | No protocol conversion. A route whose upstreams disagree on protocol cannot be saved, and at runtime a differing upstream is skipped as `protocol-mismatch` and the request fails closed. | You cannot fail over from an OpenAI-protocol primary to an Anthropic-protocol backup.                   | Give a route upstreams of the same protocol family.                                          |
| G2  | Pricing is not implemented; estimated cost appears only where the environment's existing price overrides make one computable, and only in the Model grouping.                             | No cost tracking for other groupings.                                                                   | Use token counts, which are recorded from the upstream's own reporting.                      |
| G3  | The usage view window is fixed at 24 hours and there are no charts.                                                                                                                       | No long-range trends.                                                                                   | Read `model_gateway_usage` directly; rows are retained 30 days.                              |
| G4  | A gateway provider or route cannot be deleted through settings; disabling is the retirement mechanism.                                                                                    | A stale entry stays in `settings.json`.                                                                 | Disable it, or edit `settings.json` directly.                                                |
| G5  | A route may be saved while naming a provider that no longer exists.                                                                                                                       | The route is unusable until fixed.                                                                      | Deliberate: a stale config stays reportable and fixable instead of being silently rewritten. |
| G6  | The Codex app-server probe accepts a gateway overlay but no caller supplies one, so the probe still reaches the upstream directly.                                                        | A probe may report healthy while a routed request fails.                                                | Treat the probe as a reachability check, not a routing check.                                |
| G7  | Gateway circuit-breaker state is in memory only.                                                                                                                                          | Breaker state resets on restart.                                                                        | Deliberate; a restart is the recovery mechanism.                                             |
| G8  | A non-failover upstream error body is relayed verbatim to the client.                                                                                                                     | If an upstream echoed the credential it received inside its own error body, that body would be relayed. | Pre-existing proxy behaviour, not observed in testing.                                       |

## Knowledge

| #   | Limitation                                                                                                                                                                     | Impact                                                                                                             | Workaround                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| K1  | Knowledge requires an external SAG service. Workbench does not install, bundle or start it.                                                                                    | With no SAG, there is no knowledge search at all.                                                                  | Install and run SAG, then point Settings → Integrations → Knowledge at it.                                                                                                                                                                                                                                                                                                                                                                    |
| K2  | Knowledge bases, sources, parsing and indexing happen in SAG, not in Workbench.                                                                                                | Workbench can enable, connect, test and scope knowledge, but cannot create a knowledge base in-product.            | Manage sources in SAG; select a scope in Workbench.                                                                                                                                                                                                                                                                                                                                                                                           |
| K3  | If SAG is unreachable or a source is missing, no knowledge server is attached and nothing is substituted.                                                                      | A harness silently has no knowledge tools for that thread.                                                         | Check Diagnostics before assuming a search will work; fail-closed is deliberate.                                                                                                                                                                                                                                                                                                                                                              |
| K4  | A project's Knowledge scope is applied when a harness session starts. Changing the scope, or enabling Knowledge, does not reach a session that is already running in a thread. | An agent in a long-lived thread can report the knowledge tools as unavailable after you have just configured them. | Start a new thread, or restart the thread's session, after changing the scope. Verified in both directions: with the scope set **before** the session starts, a new Codex session mounts `sag-knowledge` (`mcpServer/startupStatus/updated … "status":"ready"`) and keeps it across a clean Workbench restart and resume; with the scope set **after** the session started, the running session keeps the MCP configuration it launched with. |

## Browser

| #   | Limitation                                                                                                                                                                                                                                                                                                 | Impact                                                                                                                                | Workaround                                                              |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| B1  | No browser binary is bundled and none is downloaded at install.                                                                                                                                                                                                                                            | Without a Chromium-family browser installed, the browser tools are unavailable (`runtime-missing`).                                   | Install Chrome or Edge.                                                 |
| B2  | One browser process per thread, so many threads with browser access mean many Chromium processes.                                                                                                                                                                                                          | Memory grows with concurrently used threads.                                                                                          | Close browser use in threads you are finished with.                     |
| B3  | A profile held by a live foreign process is reported as locked; Workbench never deletes the lock or kills the process.                                                                                                                                                                                     | That thread's browser cannot start until the other process exits.                                                                     | Close the browser that owns the profile.                                |
| B4  | Playwright MCP's own stdout/stderr is logged verbatim at debug level into `logs/server.log`.                                                                                                                                                                                                               | Third-party process output (which can include page text and absolute paths, but never a Workbench credential) can reach the log file. | Set a higher log level; rotate or delete `logs/` if it matters to you.  |
| B5  | Chromium flushes its persistent profile to disk asynchronously. A write made immediately before the browser runtime is stopped can be lost; with a normal settle it survives. Verified: a value written in one session was read back after the runtime was stopped and restarted against the same profile. | A login completed in the last moments before Workbench exits might not survive; the next launch would ask you to sign in again.       | None needed in normal use — the flush happens well before a user quits. |

## Office

| #   | Limitation                                                         | Impact                                                                             | Workaround                                                      |
| --- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| O1  | Office has no Settings surface and no diagnostics vocabulary.      | You cannot tell "toolkit not wired" from "harness does not speak MCP" from the UI. | Check the harness capability view for workspace tools.          |
| O2  | High-fidelity editing of complex Office objects is not guaranteed. | A heavily formatted file may lose formatting on write.                             | Work on a copy; the original is versioned before any overwrite. |
| O3  | No Microsoft Office COM path is used.                              | No high-fidelity editing when Office is installed.                                 | None in V1.                                                     |

## Platform and packaging

| #   | Limitation                                                                                                  | Impact                                                            | Workaround                                                                            |
| --- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| P1  | Only Windows x64 is validated for V1.                                                                       | macOS and Linux are untested.                                     | None.                                                                                 |
| P2  | Building the Windows installer needs Rust, MSVC Build Tools with the Spectre libraries, Python 3 and `tar`. | A machine without them cannot produce an installer.               | Build with the project's own prerequisite probe, which names exactly what is missing. |
| P3  | No automatic backup or checkpoint is taken before a schema upgrade.                                         | A failed upgrade could leave a database you must restore by hand. | Copy the `userdata` directory before upgrading.                                       |

## Diagnostics and interface

| #   | Limitation                                                                                                                                                                                                                                                                        | Impact                                                                                                                      | Workaround                                                                            |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| D1  | Diagnostics vocabularies are per-subsystem rather than one unified enum.                                                                                                                                                                                                          | The same conceptual state is spelled differently in different panels.                                                       | Read each panel's own message.                                                        |
| D2  | The settings search sends "Diagnostics" and "Open source licenses" to `/settings/general` while the real panels are separate routes.                                                                                                                                              | Search results route to a page that links onward rather than the panel itself.                                              | Use the link from General.                                                            |
| D3  | Knowledge has both an environment entry (Integrations) and a per-project entry (Projects).                                                                                                                                                                                        | Two places can appear to control "knowledge".                                                                               | They are different levels: Integrations sets the connection, Projects sets the scope. |
| D4  | UI verification is DOM/accessibility-level, not pixel-level. All ten settings routes were exercised against a running server with zero console errors and no error copy, but the saved screenshots were not visually reviewed because the active model cannot accept image input. | A purely visual defect (spacing, clipping, colour) could exist in a panel that renders correctly in the accessibility tree. | None on this machine; report anything you see.                                        |

## Accepted upstream baseline

| #   | Item                                                                                                              | Why it does not block V1                                                                                                                                                                                                                |
| --- | ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| U1  | `usageLimitSources.managementKey` is persisted in plaintext in `settings.json` (only the client DTO is redacted). | Inherited T3 Code behaviour on an upstream code path that Phase 1–8 did not touch, and unrelated to any Workbench-added credential. Recorded rather than fixed: changing an upstream secret-storage contract is not a hardening change. |
| U2  | A provider instance has no `env` field.                                                                           | By design: harnesses read their own configuration. A harness needing an API key is configured in the harness.                                                                                                                           |
